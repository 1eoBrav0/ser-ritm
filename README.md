На снимках — отдельный тестовый профиль. Новый пользователь начинает с пустого ежедневника.

## Задача проекта

Собрать в одном приложении расписание, повторяющиеся дела и заметки. Например, работу с 15:00 до 17:00 можно добавить один раз и повторять каждый понедельник. График показывает, сколько времени занято и где события пересекаются.

Ритм — личный проект для портфолио. Его можно запустить на компьютере без Telegram. Подключение настоящего бота требует своего токена и HTTPS-сервера.

## Возможности

- Расписание дня и календарь на месяц.
- Задачи и события с интервалом времени, важностью и категорией.
- Повторения каждый день, по будням или выбранным дням недели. Изменения одного повторения или серии с выбранной даты.
- Графики загрузки дня и недели с учётом пересечений.
- Поиск, фильтры, заметки и выгрузка собственных записей в JSON.
- Напоминания в личный чат Telegram и команда `/stop` для их отключения.
- Пустой профиль при первом входе и короткое знакомство с функциями.
- Интерфейс для компьютера и телефона: боковое меню на широком экране, нижняя навигация на узком. Полный экран на ПК — если его поддерживает клиент Telegram.

## Запуск на компьютере

Нужен Python 3.11 или новее. Интерфейс не требует сборки или установки npm-пакетов.

```sh
python -m pip install -r requirements.txt
python server.py
```

Открой [127.0.0.1:8765](http://127.0.0.1:8765/). На Windows можно запустить `start.cmd`. Это локальный профиль; токен Telegram для него не нужен. `tzdata` в requirements нужен прежде всего для часовых поясов на Windows.

Для пробного открытия в Telegram: скопируй `.env.example` в `.env`, укажи токен своего бота, выполни `python install_tunnel.py`, затем `python run_telegram.py` или запусти `start-telegram.cmd`. Будет создан временный HTTPS-адрес. Такой запуск работает, пока включён компьютер. [Настройка Telegram](docs/telegram.md).

## Размещение на сервере

Подготовлен WSGI-запуск для PythonAnywhere. Команды Telegram приходят через webhook, а cron-job.org вызывает проверку напоминаний. Непрерывно работающий фоновый процесс не требуется. [Пошаговая инструкция](docs/hosting.md).

На бесплатном тарифе ограничены ресурсы, сайт нужно продлевать раз в месяц. Проверка напоминаний выполняется примерно раз в минуту, с возможными задержками. Этот вариант предназначен для небольшого проекта.

Конфигурация сервера хранится в `.env.cloud`. Образец — `.env.cloud.example`. Реальные токены, ключи и базы исключены из Git. Постоянное размещение и переключение бота ещё не завершены; локальная версия доступна для самостоятельного запуска.

## Устройство

Сервер использует стандартную библиотеку Python и SQLite. Интерфейс написан на HTML, CSS и JavaScript. Локальный HTTP-сервер и облачный WSGI-запуск используют общий обработчик API.

```text
server.py                маршруты API, HTTP-сессии, локальный сервер
cloud_wsgi.py            точка входа для хостинга
ritm/auth.py             проверка подписи Telegram initData
ritm/store.py            записи, сессии, SQLite и миграции
ritm/recurrence.py       повторения и разовые изменения
ritm/bot.py              команды и доставка напоминаний
ritm/hosting.py          WSGI, webhook, проверка очереди напоминаний
static/                  интерфейс и расчёт загрузки
tests/                   проверки на временных базах
docs/                    архитектура, настройка и принятые решения
```

Сервер определяет владельца записи по проверенной сессии. Telegram ID из тела формы не используется для выбора пользователя. Все запросы к данным ограничены владельцем.

Правила повторений хранят исходный часовой пояс IANA. Будущие записи вычисляются при просмотре; выполнение и изменения отдельной даты сохраняются независимо. Интервалы загрузки объединяются: события 15:00–17:00 и 16:00–18:00 дают три занятых часа и час пересечения.

[Подробности архитектуры](docs/architecture.md) · [Правила повторений](docs/recurrence.md) · [Проверка разных экранов](docs/responsive.md)

## Проверки

```sh
python -m unittest discover -s tests -v
node --check static/app.js
node --test tests/planner.test.cjs tests/fullscreen.test.cjs
```

Тесты проверяют подпись Telegram, раздельные профили, сохранение, повторения, интервалы времени, WSGI, защиту webhook, повторную доставку и расчёт занятости. Они используют временные базы и не отправляют реальные сообщения. Такой же запуск добавлен в GitHub Actions.

## Данные и ограничения

Локальный браузер хранит записи в `data/ritm.sqlite3`, Telegram — в `data/telegram.sqlite3`. Это разные профили. При переносе на хостинг Telegram-база передаётся отдельно от исходников. Для согласованной копии есть `backup_database.py`.

Пока нет импорта, повторений по месяцу и году, перетаскивания событий и внешних календарей. Экспорт содержит все правила серий и сохранённые исключения. В списке задач повторения показаны за открытый месяц и выбранную неделю.

При смене часового пояса устройства время пересчитывается, но день календаря автоматически не переносится. Уведомления могут задерживаться; после сбоя между отправкой и сохранением результата возможен повтор. Напоминания старше суток пропускаются.

Для большой нагрузки понадобятся другая база и более производительное размещение. Встроенный HTTP-сервер предназначен для локального запуска; на хостинге используется WSGI.
