# Интервалы времени

Добавлено 18 октября 2026 года по запросу Серафима.

## Поведение

- У задач и событий появились поля «С» и «До».
- У задачи можно не заполнять время, указать только начало или обе границы.
- У события в интерфейсе обязательны начало и конец.
- Длительность вычисляется из границ. «Работа, 15:00–17:00» занимает 120 минут.
- Интервал виден в расписании, списке и месячном календаре. Длительности задач с интервалом входят в счётчик запланированного времени.
- Форма показывает длительность сразу после выбора времени и отклоняет конец раньше или одновременно с началом.
- В форме обе границы относятся к одной выбранной дате. Создание интервалов через полночь пока не входит в этот интерфейс.

## Данные

В SQLite добавлено nullable-поле `entries.ends_at`. Оно хранит время в UTC, как и `starts_at`.
`duration` остаётся для совместимости и вычисляется сервером при получении обеих границ.
Старые события получают окончание из `starts_at + duration`; старые задачи с одним временем сохраняются без окончания.
Прежний API задания событий через длительность продолжает работать. Напоминания привязаны к началу.
Перед обновлением сохранена резервная копия базы в `data/backups/`.

## Проверка

17 автоматических тестов прошли: добавлены сохранение и изменение интервалов,
проверка неверных границ и обновление предыдущей схемы базы.
В отдельном браузерном QA-профиле создана «Работа, 15:00–17:00», проверены длительность 2 часа,
сохранение после перезагрузки и отказ сохранить окончание 14:00 при начале 15:00.
Мобильная форма проверена при ширине 390 пикселей. Эти тестовые записи не добавлялись в основной профиль.
