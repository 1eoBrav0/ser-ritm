# Повторения и загрузка · v2.2

Серии хранят правило и шаблон в SQLite отдельно от отдельных записей. Повторения за открытый период вычисляются при чтении; это позволяет хранить бессрочное правило без создания тысяч строк заранее. Изменённое или выполненное повторение сохраняется с устойчивым идентификатором `series_id:YYYY-MM-DD`. Удалённое повторение сохраняется как скрытое исключение, поэтому после перезапуска оно не появляется снова.

Изменение «К этой и следующим» завершает старую серию предыдущим днём и создаёт новую с выбранной даты. Проверка и обе операции выполняются в одной транзакции. Неверная новая настройка откатывает изменение целиком. Предыдущие записи и сохранённая история выполнения остаются. Будущие выполненные исключения сохраняются как история; новая серия может содержать другое запланированное дело в тот же день.

Дни недели: 0 — понедельник, 6 — воскресенье. Начальная дата включается, только если подходит под правило. Дата окончания включительна. Заметки не повторяются. Поддерживаются задачи без времени, с одним временем и полным интервалом. Для изменения будущей части нужно оставить дату выбранного повторения; разовое изменение может переносить конкретный день.

Часовой пояс сохраняется по имени IANA; UTC-время вычисляется заново для каждого дня. Местное время сохраняется при сезонном переводе часов. Несуществующее время весеннего перехода пропускается, неоднозначное время осеннего перехода выбирает первое вхождение. Нужен tzdata на Windows, если в Python отсутствует база IANA. Для напоминаний сервер материализует наступившие повторения независимо от открытого календаря. Флаги доставки и повторных попыток индивидуальны.

API: `GET /api/entries?from=YYYY-MM-DD&to=YYYY-MM-DD` вычисляет повторения за период до 400 дней. Одноразовые записи и сохранённые исключения возвращаются независимо от периода. Без параметров берётся текущая дата минус 7 / плюс 60 дней. Клиент загружает открытый месяц (42 дня сетки) и выбранную неделю, если она отдельно. Бессрочность относится к правилу, а не к бесконечному списку в интерфейсе.

`PUT /api/entries/<id>` с `scope=one` меняет одно повторение; `scope=future` завершает прежнюю часть и применяет новое правило. `DELETE /api/entries/<id>?scope=one|future` удаляет повторение или останавливает будущую часть. Все запросы ограничиваются владельцем из сессии. Переданные клиентом `user_id`, `series_id` и `id` не назначают владельца и не связывают чужие записи.

`GET /api/export` выгружает все правила и реальные сохранённые записи/исключения владельца, включая скрытые исключения. Сессии и служебные поля доставки не экспортируются. Автоматического импорта нет.

График считает объединение интервалов по точному времени. Пересечением считается длительность, когда одновременно заняты хотя бы два дела, без умножения на количество дел. Примыкающие интервалы не конфликтуют. Выполненные дела остаются частью расписания. Дела без полного интервала не включаются в занятые часы. Подписи шкалы дня рассчитаны на обычный 24-часовой день; в день сезонного перевода часы считаются по фактической длительности. Для Asia/Yakutsk сезонного перевода нет.

Проверено: 29 Python-тестов, 16 проверок расчёта графика в Node. Среди сценариев — понедельники 15–17, будни и каждый день, окончание серии, 2031 год, отдельное выполнение, перенос одного повторения, сохранение удаления, изменение будущей части, откат ошибочного изменения, изоляция пользователей, часовые пояса/DST, напоминания без открытой страницы, HTTP-маршруты и полный экспорт. Реальная доставка в Telegram не проверялась: токен не подключён.
