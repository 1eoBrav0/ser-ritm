# Запуск на Render и Supabase

Render запускает Python-приложение, Supabase хранит PostgreSQL. Локальный запуск по-прежнему использует SQLite. База не хранится на диске бесплатного Render: этот диск очищается при перезапуске.

Оба сервиса нужны на тарифе Free. У Render есть лимит часов работы, а после простоя приложение может долго открываться. У Supabase — лимит 500 MB базы и пауза после недели без активности. Для небольшого проекта этого достаточно, но гарантии непрерывной работы нет.

## База

Создай проект Supabase на Free. Data API не нужен: приложение обращается к PostgreSQL с сервера. В Connect выбери Session pooler, порт 5432 — он работает с IPv4. Сохрани строку подключения с паролем только в закрытых переменных окружения.

Таблицы приложения находятся в схеме `ritm`, отдельно от `public`. Доступ браузерным ролям Supabase закрыт. Пользователей по-прежнему проверяет сервер Ритма через подпись Telegram; Supabase Auth не используется.

## Приложение

Создай Web Service из `1eoBrav0/ser-ritm`, ветка `main`, Python, план Free.

- Build: `pip install -r requirements-cloud.txt`
- Start: `gunicorn cloud_wsgi:application --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 60 --access-logfile /dev/null`
- Health check: `/api/health`
- Переменные: `BOT_TOKEN`, `DATABASE_URL`, `WEBHOOK_SECRET`, `CRON_SECRET`.

Для двух последних ключей нужны разные случайные строки длиной не менее 32 символов. Адрес приложения берётся из `RENDER_EXTERNAL_URL`. При необходимости можно задать собственный `PUBLIC_URL`.

`render.yaml` содержит те же настройки для Blueprint. Токены и пароль базы в него не добавляются. Без DATABASE_URL приложение на Render откажется запускаться, чтобы случайно не использовать временную SQLite-базу.

## Перенос записей

Останови прежний Telegram-запуск и сделай согласованную копию SQLite через `backup_database.py`. Затем передай DATABASE_URL через окружение и запусти:

```sh
python migrate_to_postgres.py /закрытая/папка/telegram.sqlite3
```

Перенос разрешён только в пустую базу. При ошибке транзакция откатывается, исходный файл не изменяется. Копируются профили, серии и записи. Старые сессии не копируются: при следующем входе Telegram создаст новую.

## Бот и напоминания

После проверки HTTPS и переноса базы установи webhook и меню бота на новый адрес. Секрет webhook должен совпадать с WEBHOOK_SECRET на сервере. Для отправки напоминаний настрой cron-job.org: POST `/internal/reminders` раз в минуту с заголовком `Authorization: Bearer CRON_SECRET`.

Токен и строку подключения в cron-job.org передавать не нужно. Не запускай одновременно старый polling и облачный webhook.

Проверки PostgreSQL запускаются в GitHub Actions на отдельной тестовой базе: сохранение, разделение пользователей, повторения, доставка, блокировки, откат транзакций и перенос SQLite.


Для Supabase укажи в конце DATABASE_URL `?sslrootcert=certs/supabase-ca-2021.crt` (или `&sslrootcert=...`, если параметры уже есть). Сертификат взят из официального раздела SSL configuration. Проверка сертификата и имени сервера остаётся включённой.
