# Бесплатный запуск на PythonAnywhere

Приложение использует Python, SQLite и WSGI. Telegram присылает команды на webhook. Напоминания проверяет защищённый HTTP-обработчик, который вызывает cron-job.org примерно раз в минуту. В облаке нет бесконечного фонового процесса и временного туннеля.

Подготовленная конфигурация ещё не означает, что сайт опубликован. До переноса сохраняй работающий запуск с компьютера.

## Ограничения бесплатного размещения

По условиям на 19 октября 2026 года у нового бесплатного аккаунта PythonAnywhere один сайт, один web worker, 512 MiB диска и 100 CPU-секунд. Срок сайта нужно продлевать раз в месяц. SQLite доступна, но хостинг не рекомендует её для нагруженного production. Этот вариант подходит для небольшого учебного проекта. Если пользователей станет много, потребуется другой тариф или сервер.

У новых бесплатных аккаунтов нет встроенных задач по расписанию. Для них используется cron-job.org. Примерно раз в минуту он отправляет POST на служебный обработчик. Время доставки не гарантируется: возможны задержки при сбоях сервисов или исчерпании лимитов. За один запуск отправляется не более двух уведомлений, чтобы не занять бесплатный web worker надолго. При большой очереди она будет уходить постепенно.

Официальные страницы: [тариф](https://help.pythonanywhere.com/pages/FreeAccountsFeatures/), [SQLite](https://help.pythonanywhere.com/pages/KindsOfDatabases), [разрешённый Telegram API](https://www.pythonanywhere.com/whitelist/), [планировщик](https://cron-job.org/en/faq/).

## Аккаунты и исходники

Зарегистрируй бесплатные аккаунты [PythonAnywhere](https://www.pythonanywhere.com/registration/register/beginner/) и [cron-job.org](https://cron-job.org/). Ввод пароля, проверку почты и принятие условий владелец выполняет сам. Код хранят в репозитории `ser-ritm` на GitHub. Пароли аккаунтов и токен Telegram не нужны в репозитории.

В Bash-консоли PythonAnywhere клонируй свой репозиторий в `/home/ИМЯ/ser-ritm`. Если он закрытый, настрой отдельный доступ для чтения; не делай токен частью адреса Git. Выбери Python 3.11 или новее. Например:

```sh
git clone https://github.com/1eoBrav0/ser-ritm.git
cd ser-ritm
python3.13 -m unittest discover -s tests -v
```

В Linux часовые пояса IANA обычно уже доступны. Если выбранному Python они недоступны, создай virtualenv и установи `requirements.txt`.

## Секреты на сервере

Скопируй `.env.cloud.example` в `.env.cloud` в папке проекта на хостинге. Заполни его через закрытый редактор файлов:

- `BOT_TOKEN` — токен @serritmbot. Если он раньше попал в переписку, сначала перевыпусти его в BotFather.
- `PUBLIC_URL` — `https://ИМЯ.pythonanywhere.com`, точный адрес из панели Web, без пути и параметров.
- `WEBHOOK_SECRET` и `CRON_SECRET` — два разных случайных ключа. Для каждого можно выполнить `python3.13 -c "import secrets; print(secrets.token_urlsafe(32))"` в своей консоли. Не публикуй их в чате или логах.
- `DATA_DIR=data` — каталог постоянной базы, относительно папки проекта. Можно указать абсолютный путь за пределами checkout, если планируется пересоздание папки исходников.

Файл `.env.cloud` не выдаётся через HTTP, исключён из Git и архивов. Отдельный `.env` для запуска на компьютере не используется облачной версией. Демо-вход в WSGI всегда выключен.

## Сайт

На вкладке Web нажми Add a new web app → Manual configuration → Python 3.11+.

В WSGI configuration file оставь:

```python
import sys
project = '/home/ИМЯ/ser-ritm'
if project not in sys.path:
    sys.path.insert(0, project)
from cloud_wsgi import application
```

Подставь своё имя. Если используется virtualenv, укажи его в панели Web. Нажми Reload. Встроенный `server.py` на хостинге запускать не нужно. Не создавай static mapping для корня проекта: конфигурация и база не должны попадать в раздачу файлов. Обычные статические файлы безопасно отдаёт приложение.

До переключения бота выполни:

```sh
cd ~/ser-ritm
python3.13 deploy_pythonanywhere.py
```

Он проверяет HTTPS, `/api/health` и отказ анонимному доступу. Команда без `--activate` не меняет настройки Telegram.

## Перенос существующих записей

Локальный браузер и Telegram имеют разные базы. Переносить нужно `data/telegram.sqlite3` от текущего Telegram-запуска. `data/ritm.sqlite3` локального браузера содержит другой профиль и автоматически не переносится.

Когда новый сайт проверен, останови старый Telegram-процесс. Создай согласованную копию:

```sh
python backup_database.py data/telegram.sqlite3
```

Получившийся файл — закрытые пользовательские данные. Передай его только в свой аккаунт хостинга и положи как `data/telegram.sqlite3` (или в настроенный DATA_DIR), сохранив отдельную копию прежней базы. Не загружай базу на GitHub, в публичный архив или в static. После переноса нажми Reload сайта.

## Подключение Telegram

После остановки старого запуска и переноса базы:

```sh
python3.13 deploy_pythonanywhere.py --activate
```

Скрипт обновляет меню и команды, затем устанавливает webhook с секретным заголовком. Чужой webhook он не заменяет. Неотправленные обновления Telegram сохраняются. Повторный запуск для этого же сайта разрешён.

Отправь `/start` в @serritmbot и открой приложение. Оно должно показывать записи твоего Telegram-профиля. Старые кнопки из чата могут вести на прежний временный адрес — используй обновлённое меню или `/app`.

## Напоминания

В cron-job.org создай задачу:

| Поле | Значение |
| --- | --- |
| Название | Ser Ритм — напоминания |
| URL | `https://ИМЯ.pythonanywhere.com/internal/reminders` |
| Расписание | Каждую минуту |
| HTTP method | POST |
| Header | `Authorization: Bearer ЗНАЧЕНИЕ_CRON_SECRET` |
| Уведомления о сбое | Включить в аккаунте владельца |

Cron-job.org получает только отдельный ключ для проверки напоминаний. Токен бота и базу туда передавать не нужно. Ответ обработчика содержит только результат и количество отправленных уведомлений, без названий задач или пользователей. Не добавляй секрет в URL — он попадёт в историю запросов.

Запусти задачу вручную, затем создай в Mini App запись с напоминанием на 2–3 минуты вперёд. После проверки выключи старый локальный запуск. Не запускай `start-telegram.cmd`, пока у бота установлен облачный webhook.

## Обновления и резервирование

Перед обновлением делай резервную копию SQLite и скачивай её в закрытую папку SER. Затем `git pull --ff-only`, тесты и Reload в панели Web. Код и база обновляются отдельно; обычный git pull не трогает исключённые `.env.cloud` и `data/`.

Записи не отправляются на GitHub. Хостинг хранит базу и конфигурацию в твоём аккаунте. Все запросы к данным ограничены владельцем сессии, подпись Telegram проверяется сервером.

При сбое между отправкой сообщения и отметкой доставки возможно повторное уведомление; гарантии «ровно один раз» нет. Webhook хранит номера завершённых обновлений, а пересекающиеся проверки напоминаний защищены краткой блокировкой. Старые уведомления за пределами суток пропускаются.
